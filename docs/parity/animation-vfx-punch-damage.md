## Implementation and falsifiable integration

**src/animation/mcd-punch-damage-events.js** exports **planMcdPunchDamageEvents**. Its caller must supply exact owner/path ID, already prepared *source-clip* previous/current times, plus four independent positive qualification facts: active clip, prepared interval, active GameObject, receiver method bound. Unknown/missing facts never silently enable the branch. The return value contains **conditional method invocation requests** for setting the MeleeDamage field; it does not execute callbacks, infer a collision window from wall-clock time, modify a live Animator, play sound or render a VFX.

**tests/animation-mcd-punch-damage-events.test.mjs** checks the exact two serialized boundaries, first/last inclusion, reverse order, a skipped-frame dual event, equal-time no-op, wrong clip, missing qualification, invalid data and partitioning. Passing tests is evidence for the Web module only.

**SH-05/SH-03 handoff:** on one real Containers run, record an ordered instance-local receipt **actor → active Animator/clip 468/state/weight → prepared previous/current clip times → actual event receiver → MeleeDamage flag writes → active melee collider → damage/contact**, with timestamps and paired camera frames. Only if the instance reaches those callbacks may SH-05 route these commands to SH-03's collision window. A hit without the flag, a different selected source clip, a receiver that never fires, or a missing weight-gated interval refutes naive use of this plan. Source binary, decompiled bodies and native assets remain private.
